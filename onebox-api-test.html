ONEBOX API integration

Three read-only calls power the fan-alert pipeline: authenticate against the channel, list available matches, and inspect seat availability per grada. All requests target api.oneboxtds.net.

POST/oauth/token GET/catalog-api/v1/sessions GET/catalog-api/v1/sessions/{id}/availability
POST /oauth/token 1 · Authentication

Exchanges the channel credentials for a short-lived OAuth2 bearer token. Note the non-standard shape: channel_id and client_id are sent as separate form fields — client_id is the fixed string seller-channel-client for every tenant, and the per-tenant identifier travels in channel_id. Tokens expire after 43199 seconds (~12 hours).

Request 
POST https://api.oneboxtds.net/oauth/token

// Headers
Content-Type: application/x-www-form-urlencoded
Accept: application/json

// Body (urlencoded)
grant_type=client_credentials
client_id=seller-channel-client
channel_id=2287
client_secret=<REDACTED>
Response 200 OK 
{
  "access_token": "<REDACTED — JWT bearer>",
  "token_type": "bearer",
  "expires_in": 43199,
  "scope": "api-channels-all api-distribution-all api-catalog-all api-external-all api-gateway api-customers-mgmt-all api-orders-mgmt-all",
  "authInfo": "<REDACTED>",
  "jti": "<REDACTED>"
}
GET /catalog-api/v1/sessions 2 · List of matches

Returns every session (match / event) currently published on the channel, with full event metadata, venue, sale window, pricing, and a top-level availability summary per grada under availability.price_types[]. This is the primary feed for the alert engine.

GET /catalog-api/v1/sessions/{sessionId}/availability 3 · Seats per match

Drills into a single session and returns availability counts for every grada (price_types) and every individual sector (sectors). Useful when an alert needs sector-level granularity beyond the grada totals already exposed in /sessions.
